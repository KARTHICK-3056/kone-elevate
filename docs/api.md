# API reference

Base URL: `http://localhost:8000/api/v1`

Interactive documentation is generated by FastAPI:

- Swagger UI: <http://localhost:8000/docs>
- ReDoc: <http://localhost:8000/redoc>
- OpenAPI schema: <http://localhost:8000/openapi.json>

**Authentication.** None is enforced in the prototype. An optional `X-Actor`
header records who performed an action in the audit chain; it defaults to
`system`. This is a documented limitation, not a security design.

---

## Conventions

**Errors** are always JSON, never a stack trace:

```json
{
  "error": "validation_error",
  "message": "The request payload failed validation.",
  "issues": [
    { "field": "operating_hours", "message": "Input should be greater than or equal to 0", "type": "greater_than_equal" }
  ]
}
```

| Status | `error` | Meaning |
|---|---|---|
| 404 | - | Record not found (`detail` carries the message) |
| 409 | `conflict` | Duplicate serial number, or a lifecycle move the state machine forbids (e.g. a removed component set back to `ACTIVE`) |
| 422 | `validation_error` | Payload failed validation; see `issues` |
| 500 | `internal_error` | Unhandled fault (logged server-side, not exposed) |
| 501 | `not_implemented` | Documented future capability (sensor ingestion) |
| 503 | `database_unavailable` | Database unreachable |

**Component identifiers.** Every `{component_id}` path segment accepts the
business id (`KE-MOT-000012`), the serial number, or the QR token - a scanned
label always resolves.

## Health and metadata

### `GET /health`

```json
{
  "status": "ok",
  "app": "KONE ELEVATE",
  "version": "1.0.0",
  "database": { "connected": true, "dialect": "sqlite", "error": null },
  "model": {
    "model_available": true,
    "model_version": "RF-v1.0-synthetic",
    "accuracy": 0.8215,
    "f1_macro": 0.8252,
    "training_records": 8000,
    "data_source": "synthetic"
  },
  "data_notice": "Prototype uses synthetic degradation data. ..."
}
```

`status` is `degraded` when the model is missing but the database is up.

### `GET /health/ready`

Readiness probe. Reports whether components and audit records exist.

### `GET /meta/enums`

Every controlled vocabulary in one request: component types, materials,
recommendations, lifecycle statuses, service event types, safety-critical types,
the safety gate message and the disclaimers.

## Components

### `GET /components`

Search, filter, sort and paginate.

| Query parameter | Type | Notes |
|---|---|---|
| `search` | string | matches component id, serial, manufacturer or origin |
| `component_type` | string[] | repeatable |
| `material` | string[] | repeatable |
| `current_status` | string[] | repeatable |
| `recommendation` | string[] | filters on the **latest** prediction |
| `location` | string | partial match |
| `safety_critical` | bool | true = only safety-critical types |
| `min_health`, `max_health` | float | 0-100 |
| `installed_from`, `installed_to` | date | |
| `sort_by` | string | `component_id`, `component_type`, `material`, `health_score`, `installation_date`, `operating_hours`, `current_status`, `created_at`, `updated_at` |
| `sort_dir` | string | `asc` or `desc` |
| `page`, `page_size` | int | default 1 / 25, max 200 |

```json
{
  "items": [
    {
      "component_id": "KE-MOT-000001",
      "component_type": "Motor",
      "material": "Steel",
      "component_age": 3.0,
      "health_score": 99.1,
      "current_status": "ACTIVE",
      "is_safety_critical": false,
      "recommendation": "CONTINUE_USING",
      "recommendation_label": "Continue Using – No Changes Required",
      "material_grade": null,
      "material_grade_label": "Induction motor, copper winding, Class F (industry standard - assumed, not recorded)",
      "confidence": 0.9824,
      "safety_flag": false
    }
  ],
  "total": 60, "page": 1, "page_size": 25, "pages": 3
}
```

### `GET /components/{component_id}`

Full record including derived `component_age`, `days_since_last_service`,
`is_safety_critical` and the embedded `latest_prediction`.

### `POST /components`

```json
{
  "component_type": "Motor",
  "material": "Steel",
  "manufacturer": "KONE MonoSpace",
  "origin": "Chennai Plant",
  "installation_date": "2018-04-12",
  "location": "Chennai, India",
  "operating_hours": 18000,
  "load_cycles": 140000,
  "average_load": 650,
  "vibration": 3.8,
  "temperature": 52,
  "service_count": 5,
  "repair_count": 1,
  "failure_history": 0,
  "inspection_score": 82,
  "run_initial_prediction": true
}
```

Returns `201`. On creation the service allocates a readable component id and a
QR token, writes a `CREATE` audit entry, records an `INSTALLATION` event when
an installation date is given, and (by default) runs an initial assessment.

### `PUT /components/{component_id}`

Partial update. Only changed fields are written, and the audit snapshot records
the before/after of each one. A change limited to `current_status` is recorded
as `STATUS_CHANGE` rather than `UPDATE`.

### `DELETE /components/{component_id}`

Removes the component and its dependent rows. The deletion itself is appended
to the audit chain, and prior history stays verifiable.

### `GET /components/export`

CSV export of the whole portfolio, including the latest recommendation.

### `GET /components/filters`

Distinct locations and manufacturers for the filter controls.

## Service history

### `GET /components/{component_id}/service-events`

```json
{
  "component_id": "KE-MOT-000001",
  "total": 8,
  "items": [
    {
      "id": 42,
      "event_type": "INSPECTION",
      "event_date": "2026-06-18",
      "technician": "R. Karthik",
      "description": "Annual statutory inspection.",
      "operating_hours": 19850,
      "vibration": 4.1,
      "temperature": 55,
      "inspection_score": 78
    }
  ]
}
```

### `POST /components/{component_id}/service-events`

Body as above plus `update_component` (default `true`). When enabled the
readings are absorbed into the component record, the service or repair counter
increments, and the lifecycle status advances for `REMOVAL` (→ `REMOVED`) and
for a safety-critical `INSPECTION` (→ `UNDER_INSPECTION`).

Returns `201`. Appends a `SERVICE_EVENT` audit entry.

## Prediction

### `POST /predict`

Ad-hoc assessment; no stored component required.

**Request**

```json
{
  "component_type": "Motor",
  "material": "Steel",
  "component_age": 5.2,
  "operating_hours": 18000,
  "load_cycles": 140000,
  "average_load": 650,
  "vibration": 3.8,
  "temperature": 52,
  "service_count": 5,
  "repair_count": 1,
  "failure_history": 0,
  "inspection_score": 82,
  "days_since_last_service": 90
}
```

**Response** (abridged)

```json
{
  "recommendation": "COMPONENT_RECOVERY",
  "recommendation_label": "Component Recovery",
  "recommendation_text": "Recover usable sub-components from this motor after inspection and testing. Suitable recovered parts may be redirected to lower-demand applications where technically appropriate. The complete component is not refurbished or supplied again.",
  "decision_flow": {
    "recommendation": "COMPONENT_RECOVERY",
    "applied": true,
    "steps": [
      { "gate": "Suitable for its current application?", "passed": false, "evidence": "Classifier: 5% probability it is fit to continue; most likely is Component Recovery." },
      { "gate": "Usable individual sub-components recoverable?", "passed": true, "evidence": "A motor is an assembly of separable sub-components. Its material grade is not recorded, so which parts are recoverable is decided at inspection rather than named here. Classifier judges the parts serviceable with 97% probability (needs 50%)." }
    ],
    "subcomponents": { "possible": true, "parts": [] }
  },
  "underlying_recommendation": "COMPONENT_RECOVERY",
  "confidence": 0.92,
  "abstained": false,
  "prediction_set": ["COMPONENT_RECOVERY"],
  "health_score": 78,
  "health_band": "GOOD",
  "safety_flag": false,
  "safety_message": null,
  "safety_note": "No mandatory safety flag for this component type.",
  "key_factors": [
    {
      "factor": "Vibration",
      "feature": "vibration",
      "impact": "moderate",
      "description": "Vibration of 3.80 mm/s is elevated but not severe (limit 7.0 mm/s).",
      "value": 3.8,
      "unit": "mm/s RMS",
      "deviation_ratio": 0.543,
      "model_importance": 0.0907
    }
  ],
  "shap_factors": [
    { "factor": "Inspection Score", "feature": "inspection_score", "shap_value": 0.167, "direction": "increases_risk" }
  ],
  "cost_analysis": {
    "cost_optimal_recommendation": "COMPONENT_RECOVERY",
    "expected_cost_by_class": { "CONTINUE_USING": 1.2, "COMPONENT_RECOVERY": 0.4, "MATERIAL_RECOVERY": 2.8, "DISPOSE": 6.1 },
    "cost_matrix_version": "v1"
  },
  "probabilities": { "CONTINUE_USING": 0.05, "COMPONENT_RECOVERY": 0.92, "MATERIAL_RECOVERY": 0.02, "DISPOSE": 0.01 },
  "model_version": "RF-v1.0-synthetic",
  "model_available": true,
  "health_breakdown": [ { "factor": "vibration", "weight": 0.16, "penalty_points": 6.95 } ],
  "health_methodology": "Prototype health score is a synthetic/demo scoring methodology ...",
  "explanation_method": "key_factors blends Random Forest feature importance with deviation from documented design envelopes. shap_factors is a second, independent method: genuine per-prediction SHAP (Shapley value) attribution from one representative fold of the calibrated model.",
  "disclaimer": "AI-assisted end-of-use recommendation. Advisory only ...",
  "data_notice": "Prototype uses synthetic degradation data ...",
  "impact": { "estimated_recovery_value": 83250.0, "estimated_co2_avoided_kg": 321.1, "estimate_basis": "Prototype estimate" }
}
```

Query parameter `top_factors` (1-13, default 4) controls how many explanation
factors are returned.

**Abstention.** When the calibrated top-class confidence is low or the
split-conformal prediction set contains more than one plausible class,
`recommendation` becomes `"DEFER_TO_INSPECTION"` and `abstained` is `true`.
`underlying_recommendation` still carries the model's own best guess (for
audit purposes) and `prediction_set` lists every class that was not ruled
out. See `app/ml/abstention.py`.

**Safety-critical response.** For `Steel Rope`, `Brake` or `Governor` the
response always carries:

```json
{
  "recommendation": "CONTINUE_USING",
  "safety_flag": true,
  "safety_message": "MANDATORY HUMAN INSPECTION",
  "safety_note": "AI recommendation: Continue Using – No Changes Required. Human inspection required before this recommendation is acted on. This component type is safety-critical and cannot be released on an AI recommendation alone."
}
```

The model output is never suppressed or altered - the requirement is added
alongside it.

### `POST /components/{component_id}/predict`

Same response shape, plus `component_id`, `prediction_id` and `predicted_at`.
Persists an immutable prediction row, refreshes the cached health score and
appends a `PREDICT` audit entry - all in one transaction.

### `POST /predict/batch`

Up to 200 payloads in one request; returns an array of responses.

### `GET /components/{component_id}/predictions`

Assessment history, newest first.

### Model metadata

| Endpoint | Returns |
|---|---|
| `GET /model/info` | version, training provenance, headline metrics |
| `GET /model/metrics` | full metrics report including the confusion matrix, calibration, conformal, abstention, cost analysis and cohort validation |
| `GET /model/feature-importance` | Gini, permutation and SHAP importance, side by side |
| `GET /model/calibration` | reliability diagram bins, Brier score, conformal threshold, abstention and cost-analysis summary |
| `POST /model/reload` | reload the model from disk after retraining |

### Forecast

Weibull AFT survival model over the at-risk fleet. See
[`docs/forecasting.md`](forecasting.md) for method, validation and limits.

| Endpoint | Returns |
|---|---|
| `GET /forecast/eol?horizon=&group_by=type\|site\|region` | Expected removals per quarter with intervals, plus `current_backlog` (components already past threshold, reported separately) |
| `GET /forecast/capacity?horizon=` | Utilisation per quarter, bottleneck component type, levelled intake schedule |
| `GET /forecast/model?full=` | Fit summary (shape *k*, coefficients) and the published backtest |
| `POST /forecast/reload` | Reload the forecaster after retraining |

All forecast endpoints return `503` with a remediation hint when no forecast
model has been trained, rather than failing at import - a fresh clone serves
the rest of the API normally until `scripts/train_forecast.py` has been run.
| `GET /predictions/recent` | latest assessments across the fleet |
| `GET /predictions/export` | CSV export of every prediction |

## Passport

### `GET /passports/{component_id}`

The complete digital passport: component record, QR metadata, an inline
`qr_data_uri`, service events, prediction history, audit trail, the prototype
impact estimate, the safety flag and both disclaimers.

### `GET /passports/{component_id}/qr`

Returns `image/png`. Query parameters: `box_size` (2-24, default 10) and
`download` (sends a `Content-Disposition` attachment header).

The encoded payload is `{QR_BASE_URL}/passport/{component_id}`.

### `GET /passports/{component_id}/qr/info`

```json
{
  "component_id": "KE-MOT-000001",
  "qr_token": "9mfop1nbjqrmlzd9gxnooqxp",
  "passport_url": "http://localhost:5173/passport/KE-MOT-000001",
  "qr_image_url": "/api/v1/passports/KE-MOT-000001/qr",
  "format": "PNG",
  "error_correction": "M"
}
```

### `GET /passports/lookup/resolve?value=...`

Resolves a scanned value - a full passport URL, a bare id, a serial number or a
QR token - to a canonical component id, so the scanner UI can navigate
reliably.

### `GET /passports/{component_id}/report`

Flattened, reporting-ready view: lifecycle, decision history,
impact estimate and the audit head hash.

## Audit

### `GET /audit/verify`

Recomputes the whole chain.

```json
{ "valid": true, "records_checked": 227, "message": "AUDIT CHAIN VALID - every record hash recomputed successfully.", "head_hash": "21ca6039..." }
```

On tampering it identifies the first broken record:

```json
{
  "valid": false,
  "records_checked": 12,
  "invalid_record": 12,
  "invalid_position": 12,
  "reason": "snapshot_modified",
  "message": "Audit record 12 has been modified after it was written. The stored hash does not match its content.",
  "expected_hash": "...", "stored_hash": "..."
}
```

`reason` is `snapshot_modified` (content changed) or `broken_link` (a record
was inserted, deleted or reordered).

### Other audit endpoints

| Endpoint | Purpose |
|---|---|
| `GET /audit` | paginated chain (filter by `entity_type`, `action`) |
| `GET /audit/{entity_type}/{entity_id}` | history for one entity |
| `GET /audit/stats` | totals by action and entity type, plus the head hash |
| `GET /audit/export` | CSV export in chain order |
